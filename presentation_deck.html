Architectural Pillars of the Swimlane
01
Parallel Acceleration (Stage 4 & 5): Traditional QA sits idle waiting for code delivery. In QMPulse, QA authors test suites concurrently during Stage 5 using AI generation while Dev codes in Stage 4. Execution starts the exact second code lands in SIT.
02
Strict Segregation of Duties (Stage 3): A Functional Analyst can never approve their own specification. System RBAC enforces peer review by another authorized FA in the project, guaranteeing zero unvetted requirements reach development.
03
Automated Defect Write-Back (Stage 6): When a QA test step fails, QMPulse automatically creates a child ticket in Redmine with exact reproduction steps, expected vs actual behavior, logs, and screenshots—zero manual copy-pasting required.
04
Early Quality Gate via AI (Stage 2): Google GenAI reviews requirement text before peer approval to flag ambiguous statements, missing boundary conditions, or untestable logic—preventing rework before a single line of code is written.
Defect Remediation & Exception Loopback

When a test fails during Stage 06 (Execute Testing), the system initiates a closed-loop remediation cycle that preserves strict traceability without stalling the milestone:

FAIL ➔ QA marks step "Failed" ➔ System auto-creates Redmine Child Defect (#DEF-104) bound to Requirement (#REQ-42).
FIX ➔ Dev receives Redmine notification, fixes code, links commit SHA, and flips ticket to "Retest Ready".
VERIFY ➔ QA re-runs test step in Stage 07. If passed, Redmine child defect automatically updates to "Resolved".
Executive Oversight: PMO tracks live Schedule Performance Index (SPI), blocker count, and first-pass yield in real time during the loopback cycle.
